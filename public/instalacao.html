1. O que você precisa antes de começar

O Hormos roda inteiro em contêineres. O instalador cuida de tudo — inclusive de instalar o Docker, se ele não existir.

Sem o Analista IACom o Analista IA

para o Docker		 2 GB 8 GB — o que exige um aparelho de 12 GB para avaliação e 16 GB em produção, porque os 8 GB são o que sobra depois do sistema operacional

O motor semântico — correlação por significado, análise de GAP, índices e relatórios — funciona inteiro sem LLM. O Analista IA é o segundo estágio, opcional, e é ele que pede os 8 GB.

Não existe IA reduzida

O Hormos usa um único modelo para todos os pareceres. Abaixo de 8 GB o instalador recusa a IA e segue sem ela, em vez de instalar um modelo menor que devolveria parecer pior com a nossa marca. Essa checagem acontece antes de qualquer download.

2. Windows — o caminho recomendado

Nossa recomendação

No Windows, instale pelo WSL — o subsistema Linux que já vem no próprio Windows — e não pelo Docker Desktop.

Os dois funcionam, e o Docker Desktop é suportado. A recomendação tem dois motivos concretos:

  • Licença. O Docker Desktop exige assinatura comercial para empresas acima de certo porte. O Docker Engine dentro do WSL é open source e não tem essa exigência — você não herda um custo de licença só por avaliar o Hormos.
  • É onde testamos. O WSL é o caminho que o nosso instalador exercita em ambiente automatizado a cada versão. Problema que aparece ali, a gente vê antes de você.

O WSL encaminha localhost sozinho, então o navegador do Windows abre https://localhost normalmente — você não vai digitar endereço de máquina virtual nem número de IP em lugar nenhum.

Caminho A — automático (recomendado)

Um arquivo faz tudo: instala o WSL2, instala o Docker Engine dentro dele, instala o Hormos e ainda registra o certificado interno no Windows, para o navegador não reclamar.

  1. Baixe o projeto. Na página do repositório, use Code → Download ZIP, ou, se você já tem o Git:

    git clone https://github.com/hormosgrc/hormos.git

    Repositório: github.com/hormosgrc/hormos

  2. Descompacte o ZIP (se baixou por ZIP) numa pasta qualquer, por exemplo C:\hormos. Evite pasta sincronizada com OneDrive.

  3. Clique com o botão direito em install.bat e escolha Executar como administrador. Ele precisa disso para habilitar o WSL e registrar o certificado.

  4. Se o WSL ainda não existia na máquina, o instalador vai pedir para reiniciar o Windows. Reinicie e execute o install.bat de novo — ele continua de onde parou, nada se perde.

  5. Espere. Na primeira vez ele baixa o Ubuntu, o Docker e a imagem do Hormos; em conexão doméstica isso leva alguns minutos. Ao terminar, ele abre https://localhost sozinho e mostra o usuário e a senha do primeiro acesso.

Anote antes de fechar

A senha do primeiro acesso é gerada nessa instalação e aparece uma única vez na tela. Ela é de uso único: o sistema vai exigir que você defina a sua no primeiro login. Veja a seção 5.

Por esse caminho, o Hormos fica instalado dentro do WSL, na pasta /opt/hormos. Guarde esse caminho: ele aparece de novo na seção 6.

Caminho B — passo a passo manual

Use este se a política da sua empresa não permitir executar um .bat como administrador, ou se você simplesmente prefere ver cada comando. É o mesmo resultado.

  1. Instale o WSL. Abra o PowerShell como administrador e rode:

    wsl --install -d Ubuntu

    Reinicie o Windows quando ele pedir. Ao reabrir, o Ubuntu pede para criar um usuário e uma senha do Linux — anote, você vai usar a senha nos comandos com sudo.

  2. Ligue o systemd dentro do Ubuntu. Sem ele, o serviço do Docker não sobe sozinho, e o Hormos não volta depois que você reinicia a máquina. No terminal do Ubuntu:

    sudo sh -c 'printf "[boot]\nsystemd=true\n" >> /etc/wsl.conf'

    Depois, feche o Ubuntu e, no PowerShell, desligue o WSL uma vez para a mudança valer:

    wsl --shutdown

    Reabra o Ubuntu em seguida.

  3. Instale o Docker Engine dentro do Ubuntu:

    curl -fsSL https://get.docker.com | sudo sh

    Depois dê ao seu usuário permissão de usar o Docker:

    sudo usermod -aG docker $USER

    Feche o terminal do Ubuntu e abra de novo. Isso não é zelo: a permissão de grupo só passa a valer numa sessão nova, e esse é o tropeço mais comum de toda esta página.

  4. Confirme que o Docker responde:

    docker ps

    Se aparecer uma tabela vazia, está certo. Se disser permission denied, o terminal ainda é o antigo — feche e abra de novo. Se disser Cannot connect, suba o serviço com sudo service docker start.

  5. Baixe e instale o Hormos:

    git clone https://github.com/hormosgrc/hormos.git
cd hormos
./install.sh

    O instalador pergunta se o ambiente é local ou com domínio próprio, e se você quer o Analista IA. Para avaliação, aceite os padrões.

  6. Abra https://localhost no navegador do Windows e siga para a seção 5.

Se você já usa Docker Desktop

Também funciona, e nada precisa ser desinstalado. Ligue a integração em Settings → Resources → WSL integration, abra o Ubuntu e rode o ./install.sh do passo 5 acima. O docker de dentro do WSL passa a falar com o daemon do Windows, e nada é instalado no Linux.

Se você ainda não tem Docker nenhum e quer o Desktop mesmo assim, ele está em docker.com. Confira antes se a sua empresa se enquadra na exigência de assinatura comercial dele.

3. Linux (Ubuntu/Debian)

git clone https://github.com/hormosgrc/hormos.git
cd hormos
./install.sh

O instalador verifica os pré-requisitos e orienta se faltar algum. Se quiser adiantá-los:

sudo apt-get install -y docker.io docker-compose-v2 python3 openssl
sudo usermod -aG docker $USER

Depois do usermod, abra um terminal novo — permissão de grupo é fixada no login e não vale para a sessão em curso. O instalador detecta isso e se reabre sozinho dentro do grupo; se por algum motivo não conseguir, ele diz o motivo e mostra o comando exato a rodar.

4. macOS

Instale o Docker Desktop, abra-o uma vez para o motor subir, e depois:

git clone https://github.com/hormosgrc/hormos.git
cd hormos
./install.sh

No macOS não há alternativa ao Docker Desktop equivalente à do WSL, então aqui ele é o caminho normal.

5. O primeiro acesso

Abra https://localhost. O endereço http://localhost e a porta :8080 redirecionam para lá.

A senha vale para um acesso só

O instalador imprime o usuário e a senha no fim. Essa senha é gerada na sua instalação — ninguém mais a conhece, nem nós — e o sistema exige que você defina a sua no primeiro login. A tela de troca de senha aparecendo é o comportamento certo, não um erro.

Por isso: feche o terminal quando terminar, e não cole a saída da instalação em e-mail ou chamado de suporte sem apagar essa linha. Ela fica no histórico da janela.

Aviso de certificado? O appliance cria uma autoridade certificadora local e a instala no seu sistema, justamente para o HTTPS funcionar sem aviso. No Windows isso é feito no repositório do Windows — é lá que o navegador roda. Se mesmo assim o aviso aparecer, feche o navegador por completo (todas as janelas) e abra de novo: ele relê os certificados ao iniciar.

Sem chave de licença, o sistema sobe na Edição Comunidade, com a ISO/IEC 27001 completa. Não há nada a ativar.

6. Depois de instalado — parar, iniciar e acompanhar

Esta seção é para quem nunca usou Docker. São três comandos, e eles funcionam de qualquer pasta — você não precisa voltar para o diretório da instalação.

Onde a instalação mora

Como você instalouOnde abrir o terminal
Windows, caminho A (install.bat) Abra o aplicativo Ubuntu no menu Iniciar. A instalação fica em /opt/hormos.
Windows, caminho B (manual) Abra o aplicativo Ubuntu. A instalação fica na pasta hormos dentro da sua pasta pessoal.
Linux / macOS Seu terminal de sempre.

Os três comandos

Ver se está no ar:

docker compose -p sgsi-appliance-core ps

Lista cada peça e o estado dela. Up é no ar; Exited é parada.

Parar tudo (libera a memória da máquina; nada é apagado):

docker compose -p sgsi-appliance-core stop

Ligar de volta:

docker compose -p sgsi-appliance-core start

Parar não apaga nada. Seus dados ficam num volume do Docker, separado dos contêineres. Pode parar e ligar à vontade: o sistema volta exatamente como estava, com riscos, políticas, evidências e usuários no lugar.

E uma vez parado, fica parado — inclusive depois de reiniciar a máquina — até você mandar ligar. Isso é de propósito: quem desligou quer que continue desligado.

As peças, e o que cada uma faz

Você não precisa decorar isto. Serve para quando algo aparecer Exited na listagem e você quiser saber o que é.

NomeO que é
sgsi_portalO Hormos em si — as telas, os motores, os relatórios
sgsi_postgresO banco de dados. É aqui que os seus dados vivem.
sgsi_keycloakO login: usuários, senhas, SSO e MFA
sgsi_caddyA porta de entrada HTTPS (é quem atende o https://localhost)
sgsi_oauth2_portalO porteiro entre a entrada e o portal — garante que ninguém passe sem login
sgsi_configuratorAplica domínio e certificado próprios quando você pede pela área administrativa
sgsi_ollamaO Analista IA. Só existe se você instalou com IA.

Quando precisar de mais

Reiniciar tudo (equivale a parar e ligar):

docker compose -p sgsi-appliance-core restart

Ver o que o sistema está fazendo, em tempo real — é o que o suporte vai pedir se você abrir um chamado. Saia com Ctrl+C:

docker compose -p sgsi-appliance-core logs -f --tail=100 sgsi-portal

Atualizar para uma versão nova — da pasta da instalação, depois de baixar o código novo:

cd /opt/hormos        # ou a pasta onde você instalou
git pull
docker compose pull
docker compose up -d

Os dados são preservados: só os contêineres são trocados.

Remover o appliance, mantendo os dados para uma reinstalação futura:

cd /opt/hormos        # ou a pasta onde você instalou
docker compose down
Este apaga de verdade

Acrescentar -v ao comando acima (docker compose down -v) remove também os volumes — ou seja, apaga o banco de dados e tudo o que você registrou. Não há desfazer. Use apenas se quiser mesmo começar do zero.

7. Conferir a assinatura antes de rodar

Num produto de segurança, "confie em mim" não é resposta. A imagem do Hormos é assinada com cosign keyless (Sigstore), e um registro público de transparência guarda a prova. Você pode conferir antes de instalar, sem instalar o cosign — só com o Docker que já vai usar:

docker run --rm ghcr.io/sigstore/cosign/cosign:latest verify \
  ghcr.io/hormosgrc/hormos-portal:2.2.5 \
  --certificate-identity 'sgduarte7@gmail.com' \
  --certificate-oidc-issuer 'https://accounts.google.com'

A identidade do assinante está fixada no comando de propósito. Verificar sem ela provaria apenas que a imagem foi assinada por alguém — e quem publicasse a própria imagem, assinada com a própria conta, passaria no teste. Assinatura que não prende identidade é decoração.

8. Licenciar depois, se quiser

A Edição Comunidade não expira e não pede chave. Se um dia você quiser as edições pagas — LGPD, CIS, NIST, COBIT, ISO 42001, BACEN, iGovTIC-JUD, modo auditor, API — o caminho é:

  1. Fale com a gente por Planos ou em hormosgrc@gmail.com.
  2. Você recebe uma chave de licença.
  3. Cole a chave dentro do próprio sistema, na área administrativa.

Nada é reinstalado, nenhum dado se perde, e o appliance continua offline: a chave é verificada localmente, por assinatura digital, sem consultar servidor nenhum.

9. Quando alguma coisa não funciona

Reiniciei o Windows e o https://localhost não responde

É o caso mais comum, e não é defeito. O WSL não roda em segundo plano sozinho — ele sobe quando você abre uma sessão. Abra o aplicativo Ubuntu no menu Iniciar, espere alguns segundos e recarregue a página. Com o systemd ligado (o instalador faz isso), o Docker sobe junto e os contêineres voltam sozinhos.

Se ainda assim não voltarem, confira o estado e ligue:

docker compose -p sgsi-appliance-core ps
docker compose -p sgsi-appliance-core start

"permission denied" ao rodar docker

Você está no grupo docker, mas o terminal é anterior a isso — credencial de grupo é fixada no login. Feche e abra o terminal. Se não resolver, rode newgrp docker e repita o comando.

"Cannot connect to the Docker daemon"

Aqui o serviço está mesmo parado — é diferente do caso acima. No WSL:

sudo service docker start

Se precisar fazer isso toda vez, o systemd não está ligado: volte ao passo 2 do caminho B.

O navegador insiste no aviso de certificado

Feche o navegador por completo — todas as janelas, não só a aba — e abra de novo. Navegador relê os certificados do sistema só ao iniciar. Se persistir, rode sudo ./scripts/confiar-ca.sh da pasta da instalação.

A instalação parou dizendo que falta memória

É a checagem de RAM, e ela acontece antes de qualquer download, de propósito. No WSL a memória não se ajusta no Docker Desktop: crie ou edite o arquivo .wslconfig na sua pasta de usuário do Windows (C:\Users\SeuNome\.wslconfig) com:

[wsl2]
memory=12GB

Depois rode wsl --shutdown no PowerShell e reabra o Ubuntu. Ou simplesmente instale sem o Analista IA: o motor semântico, que é o que faz a correlação, funciona inteiro sem ele.

Nada disso resolveu

Escreva para hormosgrc@gmail.com com a saída do comando de estado e das últimas linhas do log (os dois estão na seção 6). Antes de colar, apague a linha da senha do administrador, se ela estiver no meio.
